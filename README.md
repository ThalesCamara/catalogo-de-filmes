## Sobre o projeto

O **CineMatch** é uma aplicação web de catálogo de obras audiovisuais. A página inicial pode ser explorada sem uma conta, enquanto usuários cadastrados podem montar sua coleção de favoritos e administrar o catálogo.

A aplicação possui um frontend responsivo em HTML, CSS e JavaScript e uma API REST desenvolvida com Java e Spring Boot. Os dados são armazenados em PostgreSQL e as senhas dos usuários são protegidas com BCrypt.

## Funcionalidades

- Catálogo público com capas, títulos e gêneros;
- página individual de cada obra com descrição e data de lançamento;
- cadastro e login de usuários;
- senhas armazenadas com hash BCrypt;
- adição e remoção de favoritos em todas as telas;
- página pessoal de filmes favoritos;
- área de gerenciamento disponível após o login;
- busca por título, gênero ou descrição;
- filtro por gênero e diferentes formas de ordenação;
- criação, edição e exclusão de obras;
- prévia da capa durante o cadastro ou edição;
- interface responsiva para computadores e celulares.

## Como executar localmente

### 1. Pré-requisitos

Instale as ferramentas abaixo:

- [Git](https://git-scm.com/downloads);
- [JDK 25](https://adoptium.net/temurin/releases/?version=25);
- [Node.js](https://nodejs.org/) 18 ou superior;
- [PostgreSQL](https://www.postgresql.org/download/);
- [pgAdmin](https://www.pgadmin.org/download/) ou outro cliente PostgreSQL.

Confirme as instalações no terminal:

```bash
java -version
node --version
npm --version
git --version
```

### 2. Baixe o projeto

```bash
git clone https://github.com/ThalesCamara/catalogo-de-filmes.git
cd catalogo-de-filmes
```

### 3. Crie o banco de dados

No pgAdmin, conecte-se ao PostgreSQL, abra o **Query Tool** e crie o banco:

```sql
CREATE DATABASE catalogo_filmes;
```

Depois, selecione o banco `catalogo_filmes`, abra um novo **Query Tool** e execute:

```sql
CREATE TABLE usuarios (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    nome VARCHAR(150) NOT NULL,
    email VARCHAR(150) NOT NULL UNIQUE,
    senha_hash VARCHAR(255) NOT NULL,
    created_at TIMESTAMP WITHOUT TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE filmes (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    titulo VARCHAR(255) NOT NULL,
    descricao TEXT,
    genero VARCHAR(100),
    data_lancamento DATE,
    capa_url TEXT,
    created_at TIMESTAMP WITHOUT TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE usuario_favorito (
    usuario_id INTEGER NOT NULL,
    filme_id INTEGER NOT NULL,
    created_at TIMESTAMP WITHOUT TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (usuario_id, filme_id),
    CONSTRAINT fk_favorito_usuario
        FOREIGN KEY (usuario_id) REFERENCES usuarios(id) ON DELETE CASCADE,
    CONSTRAINT fk_favorito_filme
        FOREIGN KEY (filme_id) REFERENCES filmes(id) ON DELETE CASCADE
);
```

### 4. Configure a conexão

Na raiz do projeto, crie um arquivo chamado `.env`:

```env
DB_URL=jdbc:postgresql://localhost:5432/catalogo_filmes
DB_USERNAME=postgres
DB_PASSWORD=sua_senha_do_postgres
```

Troque `sua_senha_do_postgres` pela senha definida na instalação do PostgreSQL. O arquivo `.env` é ignorado pelo Git e não deve ser enviado ao repositório.

### 5. Inicie o backend

No primeiro terminal, na raiz do projeto, execute:

**Windows (PowerShell):**

```powershell
.\mvnw.cmd spring-boot:run
```

**macOS ou Linux:**

```bash
./mvnw spring-boot:run
```

O Maven Wrapper baixa automaticamente a versão necessária do Maven. Quando aparecer que a aplicação foi iniciada, a API estará disponível em:

```text
http://localhost:8080
```

### 6. Inicie o frontend

Abra um segundo terminal na raiz do projeto e execute:

```bash
npx serve frontend -l 5500
```

Na primeira execução, o `npx` pode pedir autorização para baixar o pacote `serve`. Confirme com `y`.

Abra no navegador:

```text
http://localhost:5500
```

### 7. Comece a usar

1. Clique em **Entrar** e abra a aba **Criar conta**;
2. informe nome, e-mail e uma senha com pelo menos seis caracteres;
3. após entrar, clique em **Editar catálogo** na barra de navegação;
4. use **Adicionar obra** para preencher o catálogo;
5. volte à página inicial para visualizar e favoritar as obras.

## Executando os testes

Com o Java 25 configurado, execute na raiz do projeto:

**Windows:**

```powershell
.\mvnw.cmd test
```

**macOS ou Linux:**

```bash
./mvnw test
```

Os testes utilizam um banco H2 em memória e não alteram o PostgreSQL configurado no arquivo `.env`.

## Endpoints principais

| Método | Endpoint | Função |
| --- | --- | --- |
| `GET` | `/filmes` | Lista todas as obras |
| `GET` | `/filmes/{id}` | Busca uma obra |
| `POST` | `/filmes` | Adiciona uma obra |
| `PUT` | `/filmes/{id}` | Atualiza uma obra |
| `DELETE` | `/filmes/{id}` | Exclui uma obra |
| `POST` | `/usuarios` | Cadastra um usuário |
| `POST` | `/usuarios/login` | Realiza o login |
| `GET` | `/favoritos/{usuarioId}` | Lista os favoritos |
| `POST` | `/favoritos` | Adiciona um favorito |
| `DELETE` | `/favoritos/{usuarioId}/{filmeId}` | Remove um favorito |

## Solução de problemas

### O backend informa `UnsupportedClassVersionError`

O projeto utiliza Java 25. Confirme se `java -version` e o Maven estão apontando para um JDK 25.

### O backend não conecta ao banco

Confira se o PostgreSQL está em execução, se o banco `catalogo_filmes` existe e se os valores de `DB_URL`, `DB_USERNAME` e `DB_PASSWORD` estão corretos no `.env`.

### O frontend abre, mas não exibe as obras

Mantenha os dois terminais abertos. O frontend depende do backend rodando em `http://localhost:8080`.

### A porta já está sendo utilizada

Encerre a instância anterior com `Ctrl+C` antes de executar novamente o backend ou o frontend.
